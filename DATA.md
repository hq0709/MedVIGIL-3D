# Data you must supply, and how to get it

Nothing in this repository redistributes imaging. Three things are external and
all three are reproducible from scratch; this file is the exact recipe, with the
verification steps that catch a bad copy before it becomes a wrong number.

| what | size | needed for |
|---|---|---|
| MSD volumes (`imagesTr/`, `labelsTr/`) | 53 GB | any run that renders an image |
| `cfqa_*/seg_cache/` — TotalSegmentator anatomy masks | 588 files, ~600 MB | every arm that outlines or masks a target |
| model weights | 12–295 GB depending on the model set | inference |

The probe definitions (`cfqa_*/qa/`), the 2,262-probe common subset, the 243
published result files, this campaign's runs (`results_new/`) and every analysis
script **are** in the repository. `growth_matched.py`, `verify_paper_tables.py`
and `analysis/verify_claims.py` run with no external data at all.

## 1. MSD volumes

Tasks 03 (Liver), 06 (Lung), 07 (Pancreas) and 10 (Colon), from
[medicaldecathlon.com](http://medicaldecathlon.com). Two sources serve identical
tars; the mirror is far faster.

```bash
export MSD_ROOT=/path/to/MSD
mkdir -p $MSD_ROOT && cd $MSD_ROOT

# official (AWS, ~1.4 MB/s single-connection when we measured it)
#   https://msd-for-monai.s3-us-west-2.amazonaws.com/Task03_Liver.tar
# HF mirror of the same tars (~70 MB/s), needs `pip install huggingface_hub`
for T in Task03_Liver Task06_Lung Task07_Pancreas Task10_Colon; do
  hf download Novel-BioMedAI/Medical_Segmentation_Decathlon "$T.tar" \
      --repo-type dataset --local-dir .
done
```

**Verify before extracting.** Compare byte counts against the official bucket;
a mirror is only safe if it is byte-identical in size:

| tar | bytes |
|---|---|
| `Task03_Liver.tar` | 28,925,891,584 |
| `Task06_Lung.tar` | 9,163,696,640 |
| `Task07_Pancreas.tar` | 12,289,971,712 |
| `Task10_Colon.tar` | 6,242,760,704 |

```bash
for T in Task03_Liver Task06_Lung Task07_Pancreas Task10_Colon; do
  echo "$T $(stat -c%s $T.tar)"; tar -xf $T.tar
done
```

After extraction you should have 131 / 63 / 281 / 126 volumes in the four
`imagesTr/` directories, and the same counts in `labelsTr/`. The tars carry
macOS AppleDouble sidecars (`._foo.nii.gz`) which are not NIfTI; every loader
here already skips them, but do not count them as volumes.

## 2. Anatomy masks (`cfqa_*/seg_cache/`)

Excluded from the repository as regenerable bulk. Generated by TotalSegmentator
in **`--fast` (3 mm) multilabel mode** — and that mode is not a free choice.

`run_pipeline.segment` has a `fast` switch that the committed corpus does not
record, and the two modes give different surface gaps. We settled it against the
data rather than by assumption: regenerating with `--fast` reproduces the stored
`gap_mm` to a **median of 0.001 mm** (max 0.005), while full-resolution mode is
off by a median of 0.54 mm and up to 1.96 mm. So `--fast` is what the corpus was
built with, and anything else silently changes the geometry the labels refer to.

TotalSegmentator brings its own torch and nnU-Net, so keep it out of the
evaluation environment:

```bash
python -m venv --system-site-packages ~/envs/tsvenv   # reuses your torch
source ~/envs/tsvenv/bin/activate
pip install TotalSegmentator                          # 2.18.0 here
```

```bash
# volume list: {organ: [volume_id, ...]}; every id under cfqa_*/qa/ is needed
python - <<'PY'
import json, glob, os
need = {o: sorted(os.path.basename(p)[:-6] for p in glob.glob(f"cfqa_{o}/qa/*.jsonl"))
        for o in ("Task03_Liver","Task06_Lung","Task07_Pancreas","Task10_Colon")}
json.dump(need, open("volumes.json","w"), indent=1)
print({k: len(v) for k, v in need.items()})
PY

# workers coordinate by lock file, so start as many as the card and CPU allow
for i in 1 2 3 4 5 6; do
  python spatialgen/make_seg_cache.py --volumes volumes.json \
      --msd-root $MSD_ROOT --repo . --device gpu:0 --fast &
done; wait
```

~18 s per volume on an H100 in fast mode (85–90 s for the large liver series),
or a few minutes per volume on CPU with `--device cpu`, which is worth using
when the GPUs are busy — 224 cores segmented the remaining 157 volumes while the
cards ran inference.

**Verify the regenerated cache before trusting it.** This recomputes the
lesion-to-target surface gap from your masks and compares it with the committed
provenance, and reports the decision-relevant number — how many probes change
answer, not just how many millimetres moved:

```bash
python spatialgen/verify_seg_provenance.py --repo . --msd-root $MSD_ROOT \
    --organ Task03_Liver --seg-suffix "" --volumes 8
```

Expect a median absolute difference around 0.001 mm and **zero answer flips**.

## 3. Model weights

Everything loads through `transformers` from the tags in
`spatialgen/run_multimodel.py::MODEL_ID`. Put the cache somewhere with room:

```bash
export HF_HUB_CACHE=/path/with/space          # 295 GB for the full set
hf download Qwen/Qwen2.5-VL-32B-Instruct
```

| tag | model | bf16 weights |
|---|---|---|
| `qwen7b` / `internvl` / `qwen3vl` | Qwen2.5-VL-7B, InternVL3-8B-hf, Qwen3-VL-8B | 14–16 GB |
| `internvl14` / `pixtral` | InternVL3-14B-hf, Pixtral-12B | 28 / 24 GB |
| `qwen32b` | Qwen2.5-VL-32B | 64 GB |
| `aria` | Aria-25B-MoE | 50 GB |
| `qwen72b` | Qwen2.5-VL-72B | **146.8 GB — needs `--device auto` across ≥2×80 GB** |
| `m3d`, `m3dllama`, `med3dvlm` | native volumetric; also need `pip install monai` | 8–14 GB loaded |

Two that do **not** fit two 80 GB cards and are deliberately absent:
InternVL3-78B (156.8 GB) and Llama-3.2-90B-Vision (177.2 GB, and gated).

## 4. Render cache (optional, and worth it)

The identification control and the sub-task runs read montages from
`render_cache/`. Renders are a pure function of (volume, lesion, target,
condition), and without the cache every model run re-decompresses the same
quarter-gigabyte volumes — measured, that is the difference between a
GPU-bound grid and a 13-hour I/O-bound one.

```bash
python runs/prerender.py --workers 40      # ~10 min, 4,020 PNGs, 2.7 GB
```

**Purge it after any change to the renderer.** A stale cache silently feeds the
old images to every job, and the accuracies will not tell you — two different
renderings both score 50%. After purging, re-run the parity test:

```bash
rm -rf render_cache
python spatialgen/run_identification_control.py selftest
```

## 5. Environment

```bash
export MEDVIGIL3D_ROOT=/path/to/MedVIGIL-3D   # repo root is also the data root
export MSD_ROOT=/path/to/MSD
export HF_HUB_CACHE=/path/with/space
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True   # montages vary in size;
                                                          # without this a 7B job
                                                          # held 41.8 GB for 14 GB
                                                          # of weights
export OMP_NUM_THREADS=12                     # image preprocessing otherwise took
                                              # ~30 cores per job and ran the box
                                              # at load 364 with the GPUs idle
```

Tested on Python 3.13, torch 2.7.0+cu128, transformers 5.2.0, nibabel 5.4.2,
TotalSegmentator 2.18.0 (separate env), monai 1.6.0 (`--no-deps`, for the native
volumetric models only).
